# Анализ асимптотической сложности: Задача 12

## Временная сложность
**Оценка:** `O(n)` в среднем случае, `O(n²)` в худшем (теоретически), практически `O(n)`.
**Обоснование:**
1. Используется хеш-таблица `HashMap<Integer, Integer>` для хранения первого вхождения каждого значения.
2. Один проход по массиву. На каждой итерации:
   - Вычисление `need = s - arr[i]` → `O(1)`.
   - Поиск `need` в карте → амортизированное `O(1)`.
   - Вставка `putIfAbsent` → амортизированное `O(1)`.
3. Средний случай: все хеш-коды уникальны или коллизии разрешаются за константу → `O(n)`.
4. Худший случай: все ключи попадают в одну корзину (крайне маловероятно для `Integer` в Java 8+) → деградация до `O(n²)`. В учебных и боевых задачах принимается `O(n)`.
5. Логика `putIfAbsent` гарантирует сохранение минимального индекса. Возврат `{j, i}` происходит при первом совпадении, что обеспечивает лексикографически минимальную пару `(i, j)`.

## Пространственная сложность
**Оценка:** `O(n)`
**Обоснование:**
1. В худшем случае (все элементы различны и пара не найдена) карта хранит `n` пар `ключ-значение`.
2. overhead хеш-таблицы Java: массив бакетов + узлы `Node`. Константный множитель не влияет на асимптотику → `O(n)`.
